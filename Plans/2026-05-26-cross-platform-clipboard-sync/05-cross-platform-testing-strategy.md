# 第 5 轮 · 跨平台开发与测试策略

> **核心问题**：该应用需要至少 2 台设备通信，Win ↔ Mac 互测，是否每次都要发测试版到另一台？
> **答案**：不需要。单机即可完成大部分逻辑验证。

---

## 用户提问（原文）

> 这个应用在开发阶段怎么测试，我在一个平台上进行开发，但是该应用特性通常需要至少2个设备同时进行测试，更特别的是，需要windows与mac设备进行通信测试，我是否每次需要将测试版发送到另一台设备进行测试？有只需要在一台设备上进行双端测试的机制吗？

## 单机双实例测试（日常开发核心方案）

运行两个应用实例，各自使用独立的数据目录和配置：

```
# 终端 1 — 实例 A（发送模式）
cargo run -- --data-dir /tmp/planarclip-a --port 1420

# 终端 2 — 实例 B（接收模式）
cargo run -- --data-dir /tmp/planarclip-b --port 1421
```

关键配置项：

| 配置 | 实例 A | 实例 B | 说明 |
|:---|:---|:---|:---|
| `data-dir` | `/tmp/planarclip-a` | `/tmp/planarclip-b` | 独立密钥对 + 独立历史 |
| `port` | `1420` | `1421` | 避免 Tauri 端口冲突 |
| 信令服务器 | `localhost` | `localhost` | 同一台机器 |
| WebRTC | loopback | loopback | 本地直连，零延迟 |

### 剪贴板冲突解决

两个实例同时监控同一个系统剪贴板会产生竞争。对策：

| 实例 | 角色 | 行为 |
|:---|:---|:---|
| **A** | 发送模式 | 监控剪贴板，检测变更后广播 |
| **B** | 接收模式 | 仅监听网络消息，收到后写入剪贴板 |

调试时：B 写入的剪贴板内容与 A 发出的原始内容比对 → 验证同步正确性。

可通过环境变量控制：
```bash
PLANARCLIP_MODE=send   cargo run -- --data-dir /tmp/planarclip-a
PLANARCLIP_MODE=recv   cargo run -- --data-dir /tmp/planarclip-b
```

## 跨平台真机测试

| 方式 | 适用场景 | 成本 |
|:---|:---|:---|
| **CI 双平台构建** | 每次 PR / 提交自动验证编译 + 单元测试 | 零（GitHub Actions 免费） |
| **本机 + 虚拟机** | Win 开发，VM 跑 macOS（或反之） | Parallels / VMware |
| **两台物理机** | 端到端集成测试、性能测试 | 里程碑节点做一次 |

---

## 测试金字塔

```
                    ┌──────────────┐
                    │  真机跨平台     │  ← 里程碑节点
                    │  E2E 测试      │
                    ├──────────────┤
                    │  双实例集成     │  ← CI + 手动
                    │  WebRTC / 同步  │
                    ├──────────────┤
                    │  单元测试       │  ← 每次提交
                    │  加密/序列化/    │
                    │  去重/信令协议   │
                    └──────────────┘
```

### 各层能覆盖和不能覆盖的

| 层级 | 能测 | 测不了 |
|:---|:---|:---|
| **单元测试** | 加密握手、序列化、去重逻辑、信令协议解析 | 真实剪贴板、真实网络 |
| **双实例集成** | 同步引擎、WebRTC 连接、消息路由、冲突解决 | 跨平台剪贴板格式（CF_HDROP vs NSPasteboard） |
| **真机 E2E** | 真实剪贴板读写、托盘行为、NAT 穿透、性能 | — |

---

## 📌 本轮要点

- **日常开发无需发到另一台设备** — 单机双实例可覆盖 80% 测试需求
- 核心技巧：`--data-dir` + `--port` 隔离两个实例 + `PLANARCLIP_MODE` 区分收发角色
- 跨平台真实通信测试仅在里程碑节点做一次即可
- 平台无关逻辑（加密、同步、WebRTC）→ 单元测试 + 双实例
- 平台差异（剪贴板格式、托盘行为）→ CI 构建 + 阶段真机验证
