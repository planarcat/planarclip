## 网络架构：两种路线的抉择

### 路线一：自建服务器中转（Client-Server）

```
Device A ──→ Server ──→ Device B
```

| 优势 | 劣势 |
|:---|:---|
| 逻辑简单、易管理 | 持续服务器成本 |
| 轻松实现离线消息 | 大文件占大量带宽 |
| 多设备同时同步天然支持 | 数据流经服务器，存在隐私风险 |
| | 单点故障风险 |

### 路线二：点对点直连（P2P）

```
Device A ←──→ Device B        （数据不经过第三方）
```

| 优势 | 劣势 |
|:---|:---|
| 零服务器带宽成本 | 需处理 NAT 穿透 |
| 局域网 **70–100 MB/s+** | 离线消息逻辑更复杂 |
| 数据不经过第三方，隐私性强 | 多设备同步需自行协调 |

> **结论**：文件含敏感信息 + 大文件场景 → **P2P 直连是理想选择**。

---

## 推荐架构：渐进式混合方案

```
Phase 1 ───→ Phase 2 ───→ Phase 3 ───→ 未来
WebSocket     WebRTC       libp2p       QUIC
文本/小文件    P2P 大文件    完整 P2P     弱网优化
```

| 阶段 | 技术 | 目标 |
|:---|:---|:---|
| 🚀 **启动** | WebSocket | 文本 + 小文件剪贴板同步，快速跑通原型 |
| 📡 **扩展** | WebRTC | P2P 直传大文件，利用局域网高速通道 |
| 🌐 **进阶** | libp2p (Rust) | 完整 P2P 网络 + 局域网自动发现 |
| 🔧 **辅助** | QUIC | 弱网环境故障转移优化 |

## 📌 本轮要点

- 客户端：**Tauri**（性能优先）/ Electron（快速出成品）
- 网络：**P2P 直连** — 大文件 + 隐私优先，局域网 70–100 MB/s+
- 渐进路线：WebSocket → WebRTC → libp2p，兼顾短期与长期
- 参考项目：CrossPaste
