## 建议与回答

### 关于覆盖率门禁（Q2）

**是的，就是测试覆盖率。**

覆盖率门禁 = 让 `pnpm test` 或 CI 在覆盖率低于某阈值时**失败**。Vitest 用 `v8` 或 `istanbul` 采集，输出四个维度：`lines / statements / functions / branches`。

```ts
// vitest.config.ts
coverage: {
  provider: 'v8',
  thresholds: { lines: 60, functions: 60, branches: 50, statements: 60 }
}
```

作用是**防止覆盖率倒退**，不是逼你写测试。

**对 PlanarClip 的建议**：

- **暂不设阈值**：现在从 0 起步，任何阈值都会立刻卡红或没意义
- **开启覆盖率采集**（`pnpm test:web --coverage`），先把数据看清楚
- 等 2~3 周后覆盖率稳定在某个基线（比如 40%），再把阈值设为「当前值 - 5」作为回退保护

### Playwright vs tauri-driver（Q3）

| 维度 | Playwright（浏览器模式） | tauri-driver（真实桌面应用） |
|---|---|---|
| 测试目标 | `pnpm dev:web` 起的 Vite 页面 | `pnpm build` 出的 Tauri 安装包 |
| 能测什么 | 纯 UI 交互、路由、组件状态、CSS / 动效、a11y | UI + **真实 IPC** + 系统托盘 + 剪贴板 + 窗口事件 |
| **不能测什么** | ❌ Tauri `invoke` / 事件 / 剪贴板 / 托盘 / mDNS / TCP 直连 | 无明显盲区（但慢） |
| Windows 依赖 | 零（浏览器自带） | 需要装 **Microsoft Edge WebDriver**，版本要与 WebView2 严格对齐 |
| 搭建工作量 | 30 分钟 | 半天到 1 天（Windows 上驱动版本对齐容易翻车） |
| 单次运行速度 | 秒级 | 十几秒起步 |
| 稳定性 | 高 | 中（WebView2 升级会打断驱动） |
| 维护成本 | 低 | 中偏高 |

**推荐结论**：**两个都不急着做；如果要做，先 Playwright，`tauri-driver` 暂缓。**

理由：

1. PlanarClip 的核心价值在 **Rust 侧**（配对、加密、协议、传输），这些用**第 2 层 Rust 集成测试**覆盖，比 E2E 又快又稳
2. **Playwright 浏览器模式**能守住的只是「UI 冒烟」——三栏切换、配对弹层弹出、设置项改动。价值有限但成本低，可以顺手做
3. **`tauri-driver`** 是唯一能覆盖「真实 IPC + 托盘 + 剪贴板」的方案，但日常开发跑不动；且 Windows 上 Edge WebDriver 版本对齐是**已知踩坑点**，容易变技术债

**分阶段建议**：

- **短期（Step 1~3 内）**：不做 E2E，用 Rust 集成测试守住协议 + 剪贴板同步
- **中期（前三步稳定后）**：加 Playwright 浏览器冒烟，只测 UI 可见的东西
- **长期（有发布节奏后）**：再评估 `tauri-driver` 做发版前回归

### CI（Q4）

**暂不考虑**，脚本设计上仍保留可移植性（`pnpm test` / `pnpm test:web` / `pnpm test:rust` 直接可用），未来接 CI 无需改动。
