# 界面 UI 优化与 Figma 项目融入 — 待执行方案

> 生成时间: 2026-06-21
> 基于讨论: [01-ui-refresh-and-figma-integration.md](01-ui-refresh-and-figma-integration.md) | [02-design-and-make-driven-ui-refactor-plan.md](02-design-and-make-driven-ui-refactor-plan.md)

## 需求概述

基于以下两类输入，重构 `Apps/planarclip` 的前端 UI：

- Figma Design：`PlanarClip` 设计稿，当前重点参考节点为 `1:1121`
- Figma Make 产物：`Resources/PlanarClip`

本次目标不是简单“替换皮肤”，而是完成一次**桌面前端整壳重构**：以 Design 作为视觉与结构真源，以最新 Make 项目作为 React/Tailwind 实现骨架，将其迁入当前 Tauri 应用中，并把现有 Rust/Tauri 的连接、配对、设备发现与状态事件重新接回新 UI。

## 现状判断

### 已有基础

- 当前 `Apps/planarclip/src-tauri` 已具备托盘、窗口、连接状态、局域网发现、直连握手、配对码、断开连接等真实能力；
- 当前前端虽然是旧 DOM 页面，但已经完整验证过 Tauri commands/events 的基本调用链；
- 最新 `Resources/PlanarClip/src/app/App.tsx` 已不是纯静态稿，而是形成了三栏布局、设备页、设置页、配对弹层等较完整的 React 壳；
- Figma Design 已可读取到节点级，能够直接校正布局、文本、颜色、选中态与层级。

### 当前缺口

- 当前主应用前端仍是 `vite-plus + 原生 DOM`，而最新 Make 产物是 `React + Vite + Tailwind 4`；
- Make 项目中大量交互仍是 mock 数据与 `setTimeout` 演示逻辑，不可直接当作真实产品逻辑；
- 当前后端缺少一部分新 UI 想要的数据接口，例如设置读写、已信任设备列表、最近同步摘要、会话级历史；
- 当前窗口尺寸 `380 x 520` 与 Design/Make 的桌面控制台布局明显不匹配；
- 指定 Design 节点 `1:1121` 反映出“设置页激活态”已是目标结构的一部分，因此本轮不能只做剪贴板页替换。

## 技术决策

| 决策项 | 选择 | 理由 | 来源轮次 |
|--------|------|------|----------|
| 视觉真源 | 以 Figma Design 为准 | Design 是用户确认过的真实设计稿，Make 只是某一时刻的代码近似物 | 第 2 轮 |
| 前端骨架来源 | 以 `Resources/PlanarClip` 为实现起点 | 最新 Make 产物已覆盖导航、设备页、设置页、配对弹层，复用成本最低 | 第 2 轮 |
| 最终运行宿主 | 保留 `Apps/planarclip` 与 `src-tauri` | 真实桌面能力、托盘与同步链路都在当前工程中 | 第 1、2 轮 |
| 重构范围 | 本轮做整壳重构，而不是只替换单页 | Design 节点已明确三栏导航与设置态，产品结构需整体成型 | 第 2 轮 |
| UI 数据策略 | 去 mock 化，建立统一前端适配层 | 不能把假的演示逻辑直接接入生产壳 | 第 1、2 轮 |
| 真实能力接入顺序 | 先接连接/配对/LAN 主链路，再补设置与历史摘要 | 先保证可用，再逐步充实仪表盘数据 | 第 1、2 轮 |
| 设置页策略 | 本轮做最小可用设置页 | 指定 Design 节点就是设置态，不能继续把设置页当装饰 | 第 2 轮 |
| 剪贴板页策略 | 本轮仅做文本真实化与空态收敛 | 当前后端只支持文本剪贴板，不扩成图片/文件真链路 | 第 1、2 轮 |
| 窗口策略 | 调整为桌面控制台尺寸并设置合理最小值 | 当前窗口太小，无法承载目标布局 | 第 1、2 轮 |
| 风险控制策略 | 严格区分“前端壳迁移”“状态桥接”“后端补口”三层 | 降低改造时 UI、状态、接口互相缠绕的风险 | 第 2 轮 |

### 页面映射

#### 侧边栏

- 以 Design 节点 `1:1121` 为基准，还原 `剪贴板 / 设备 / 设置` 三个导航项、IP 信息、局域网设备摘要与底部主题/状态区；
- 负责全局导航与轻量状态总览，不承载重业务逻辑。

#### 剪贴板页

- 保留 Make 中的列表/网格双视图结构；
- 首期只展示文本同步相关数据；
- 图片/文件条目从“假数据卡片”调整为真实空态或未来能力占位。

#### 设备管理页

- 复用 Make 中“连接新设备 + 已配对设备列表 + 移除设备”的页面结构；
- 将局域网发现、连接发起、状态展示、断开/移除逻辑接回真实后端；
- 将配对弹层作为设备页的关键交互入口。

#### 设置页

- 以指定 Design 节点的设置态为核心参考；
- 保留背景模式、主题色与同步设置分组；
- 将设置项区分为：真实可改、前端本地可改、暂不支持；
- 不再保留会误导用户的伪开关语义。

## 实现步骤

### Phase 1：前端壳迁移与 Design 对齐
- [ ] 对照 Figma Design 节点 `1:1121` 复核侧边栏、设置页、颜色与选中态
- [ ] 梳理 `Apps/planarclip` 与 `Resources/PlanarClip` 的入口、依赖、构建差异
- [ ] 将主应用前端切到 React 入口，迁入 Make 项目的 `src/app`、`src/styles` 与必要资源
- [ ] 清理旧 DOM 页面入口，建立新的主壳组件与页面切换结构
- [ ] 调整 Tauri 窗口尺寸、最小尺寸与默认展示策略，适配桌面控制台布局

### Phase 2：去 mock 化并接回连接主链路
- [ ] 建立统一的 Tauri API 封装与事件订阅层
- [ ] 将 `get_status`、`get_pairing_code`、`get_lan_devices` 接入新 UI
- [ ] 将 `connect_lan`、`submit_pairing_code`、`reject_connection`、`disconnect` 接入真实交互
- [ ] 用真实 `connection-request / established / failed / ended` 事件替换 Make 中的模拟流程
- [ ] 用真实 LAN 设备列表替换 `PairingModal` 与设备页中的发现 mock 数据

### Phase 3：设置页最小可用化
- [ ] 保留并接通前端即可落地的设置项：背景模式、主题色
- [ ] 盘点设置页中的同步/安全项，区分“真实可配”“暂不支持”“仅展示”
- [ ] 为真实可配项补充必要的 Rust commands 与配置持久化能力
- [ ] 为暂不支持项设计禁用态、说明文案或未来版本标记
- [ ] 确保设置页与侧边栏状态信息一致，不出现视觉与实际状态冲突

### Phase 4：剪贴板页真实收敛
- [ ] 设计会话级剪贴板历史或最近同步摘要的最小数据模型
- [ ] 在不扩展图片/文件真同步的前提下，接入文本同步结果展示
- [ ] 清理误导性的远程图片与假文件条目，改为空态、示例态或真实摘要
- [ ] 保留列表/网格视图切换，但确保状态来源真实或明确标注占位
- [ ] 统一“最近同步”“来自哪台设备”“已传输到几台设备”等文案口径

### Phase 5：产品收口与验证
- [ ] 统一所有用户侧提示为自然中文，避免技术术语直接暴露
- [ ] 收口配对弹层、失败提示、断开提示、按钮禁用态与加载态
- [ ] 验证托盘打开/隐藏窗口后的 React 页面恢复是否正常
- [ ] 验证新窗口尺寸下布局稳定，且关键交互在最小尺寸内可用
- [ ] 回填 `COMPLETED.md` / `UNEXECUTED.md`，为后续锁定或继续迭代做准备

## 验收标准

- 新桌面界面以 Figma Design 为最终视觉依据，且核心页面结构与 Design/Make 一致；
- `Apps/planarclip` 不再使用旧 DOM 页面作为主入口，而是由新 React UI 接管；
- 新 UI 中的设备管理、配对弹层、设置页、导航状态都不再依赖伪业务状态；
- 现有 Rust/Tauri 主功能在新界面中可完成：查看状态、查看配对码、发现 LAN 设备、发起连接、输入配对码、拒绝连接、断开连接；
- 设置页至少有一部分真实可用项，剩余项以禁用态或说明文案清楚表达；
- 剪贴板页不再展示误导性 mock 记录，文本同步信息可真实体现或以明确空态表达；
- 窗口尺寸与整体布局适配桌面控制台使用场景。

## 风险与注意事项

- **高风险：前端范式切换。** 从原生 DOM 切到 React，涉及构建链、入口与组件边界重建；
- **中高风险：Make 去 mock 化。** 这不是变量替换，而是需要剥离一整层伪状态系统；
- **中风险：设置页范围膨胀。** 设计稿会天然暗示“所有设置都可用”，必须清楚定义本期边界；
- **中风险：新窗口形态改变产品气质。** 新版更像桌面控制台，需要同步处理窗口尺寸与信息密度；
- **范围控制提醒：** 图片/文件同步、跨网连接、公网信令、全量历史持久化不纳入本轮默认范围。
